## Can the 114 complete observations be consolidated and used?

* **Consolidated: yes.** The artifact uploads `data/`, which contains the raw
  layer (`plan.jsonl`, `events.jsonl`, run logs) that consolidation needs; all
  workflow steps succeeded. (To confirm on import: per-experiment counts and
  `artifact_rows_match`.)
* **Used for training now: no.** 114 < 167 usable rows (real-label ratios),
  < 250 (historical ratios); three categories have zero usable rows, so even a
  trainable model would be unrepresentative. They are valuable as *part* of
  the first training set and as censored evidence for the planner.

## Minimum additional data for a first defensible model

* Trainer gate: ≥ 167 usable rows under `real_label` ratios → **≥ 53 more**;
  allowing for uneven group sizes, target **≥ 80–100 more usable rows**.
* Representativeness: ≥ 4 independent usable groups in every category,
  including the three long-output categories that currently have none.
* Effort variation: at least two effort levels observed per category, so the
  effort feature is identified.
* One adaptive $2 batch on `gpt-6.1-sol` (prior-only plan: ~267 requests,
  ~$1.70 expected, ~250 expected usable rows) meets all three; the store-based
  plan should be regenerated once the first artifact is imported.
